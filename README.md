# Баланс

React-приложение для зарплаты, расходов и повторяющихся платежей. Данные остаются в браузере; бэкенд и аккаунт не нужны.

## Запуск

Используйте Node.js 22.22.2+, 24.15.0+ или 26+ согласно `engines` в package.json.

```sh
npm ci
npm start
```

Откройте http://127.0.0.1:5173. Адрес и ключ `balance-v1` сохранены: данные предыдущей версии подхватятся автоматически в том же браузере. `localhost` и `127.0.0.1` — разные хранилища; используйте прежний адрес или перенесите JSON-копию.

## Что умеет

- Доходы и расходы в рублях, категории, поиск и фильтры.
- Повторение раз в 1, 2, 3, 6 или 12 месяцев; необязательная дата окончания.
- Последний день месяца для платежей, дата которых отсутствует в коротком месяце.
- Независимые отметки оплаты/получения по месяцам, плановый и фактический остаток.
- Редактирование и удаление серии. Изменения относятся и к прошлым месяцам; завершение серии задаётся датой окончания.
- JSON-копии версии 1 совместимы с исходным приложением в обе стороны. Импорт проверяется до подтверждения замены.
- CSV для Excel содержит все операции выбранного месяца; загрузка CSV не предусмотрена.

Все суммы хранятся целым числом копеек. Остаток рассчитывается внутри выбранного месяца без переноса с предыдущего. Очистка данных сайта удаляет бюджет: регулярно сохраняйте JSON-копию. Между устройствами копии переносятся вручную.

## Архитектура

```text
src/
  app/             React-компоненты, формы, useBudget, форматирование, запуск и сборка зависимостей
  domain/          Модели, правила, расчёты, сценарии и контракты BudgetRepository / BudgetFiles
  data/            localStorage, проверка и преобразование JSON v1, CSV
```

`App → Domain ← Data`. Отдельного слоя Application нет: сценарии и контракты принадлежат Domain. Только `app/create-services.ts` импортирует конкретные реализации из Data и связывает их со сценариями; эту точку сборки вызывает `app/main.tsx`. Остальной App работает с Domain. Domain не зависит от React, DOM и Node; отдельный tsconfig проверяет это с `types: []`.

`BudgetService` читает актуальное хранилище перед изменением, применяет доменное правило и сохраняет результат. UI обновляется после успешной записи. При повреждении данных обычная запись блокируется ошибкой чтения; восстановление из проверенной копии остаётся доступно. События других вкладок подключаются и отключаются в жизненном цикле хука. Одновременная запись из двух вкладок не транзакционна: localStorage не предоставляет блокировок.

Не используются глобальный контейнер, серверный кэш или отдельная библиотека состояния: их задач в текущем приложении нет. Состояние форм и фильтров локально компонентам; бюджет хранится в `useBudget`. Категории внутри Domain имеют стабильные коды, русские названия относятся к представлению и формату файла v1.

Подробнее: [архитектура и соглашения](docs/architecture.md). Локальные правила в ai-rules/ также заполнены, но исключены из Git настройкой этого checkout.

## Проверки и сборка

```sh
npm run check
npm run build
npm run preview
```

- `check`: строгая типизация, границы импортов, Vitest и форматирование.
- `test`: календарь, расчёты, JSON/CSV, сценарии, ошибки хранилища, подписки и React-интерфейс.
- `check:architecture`: AST-проверка обычных и type-импортов, реэкспортов и динамических импортов.
- `format`: Prettier для исходников и документации. Локальные `ai-rules/` не входят в CI; общие правила не изменяются.
- `build`: статический `dist/`, включая Service Worker с хэшированным списком ресурсов.
- `preview`: готовая сборка по тому же адресу; предварительно остановите сервер разработки.

Офлайн-кэш работает у готовой сборки после первого успешного открытия. В режиме разработки он отключён, чтобы не мешать обновлению исходников. Для размещения достаточно статического хостинга с HTTPS (или loopback для локального запуска), корень сайта `/`. CI выполняет те же проверки и сборку, но не публикует приложение.

Сборка SPA через Vite соответствует [руководству React](https://react.dev/learn/build-a-react-app-from-scratch).
