# Архитектура проекта

Три слоя: `App → Domain ← Data`. Сценарии и их контракты принадлежат Domain.

## Структура и ответственность

| Слой   | Файлы и ответственность                                                                                                                                        |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| App    | src/app/: React-компоненты, формы, use-budget.ts, форматирование, DOM-выбор и скачивание файлов, запуск приложения                                             |
| Domain | src/domain/budget.ts: модели, инварианты, календарь, расчёты и чистые изменения бюджета; budget-service.ts: сценарии; ports.ts: BudgetRepository и BudgetFiles |
| Data   | src/data/: реализация localStorage, проверка и преобразование JSON v1, экспорт CSV                                                                             |

`app/create-services.ts` — точка сборки зависимостей. Она создаёт реализации Data и передаёт их сценариям Domain. `app/main.tsx` вызывает её один раз вне render и передаёт узкий BudgetService интерфейсу. Бизнес-правил в точке сборки нет. `app/offline.ts` управляет кэшем приложения.

## Разрешённые зависимости

- Domain импортирует только Domain. React, DOM, Node, App и Data запрещены.
- Data импортирует Data и Domain, реализует контракты Domain. Не зависит от App.
- App импортирует App и Domain. React разрешён только здесь.
- Единственное исключение App → Data — src/app/create-services.ts.
- Только src/app/main.tsx может импортировать create-services.ts. UI не получает контейнер зависимостей и не обходит контракт через точку сборки.
- main.tsx — точка входа, импортировать её из других модулей нельзя.
- Именованные экспорты файлов служат входами модулей; barrel-файлы не требуются.

## Сценарии и состояние

BudgetService загружает актуальный бюджет через BudgetRepository, применяет доменное правило и сохраняет результат. Только после успешной записи useBudget принимает новое состояние. При невозможности прочитать исходные данные нельзя записывать поверх них пустой бюджет. Явное восстановление из валидной JSON-копии остаётся доступно.

Подписка на изменения другой вкладки возвращает cleanup; useBudget подключает и отключает её в effect. Сервисы создаются один раз на запуск приложения, тесты получают отдельные экземпляры. Состояние форм и фильтров локально компонентам. Серверного состояния, роутера и глобального store нет: один экран, без бэкенда.

## Модели, форматы и ошибки

- readonly-модели Domain, суммы целым числом копеек, строковые ID, стабильные коды категорий.
- Внешний JSON имеет тип unknown до проверки в Data. Русские названия категорий JSON v1 преобразуются в коды Domain и обратно. Сохраняем совместимость копий и ключ balance-v1.
- BudgetError содержит код. Data переводит сбои хранилища в storage-read/write; App выбирает пользовательский текст.
- DOM-выбор и скачивание файла — App; кодирование и проверка содержимого — Data; финансовые правила и координация сценариев — Domain.

## Финансовое поведение

Редактирование и удаление относятся ко всей серии. Отметки, исключённые новым расписанием, очищаются. Оплата отмечается для конкретного месяца. Остатки между месяцами не переносятся. localStorage не обеспечивает атомарность между параллельно пишущими вкладками.

## Проверки

scripts/check-architecture.mjs проверяет направления зависимостей, точку сборки, обычные и type-импорты, реэкспорты и динамические импорты. tsconfig.core.json проверяет весь Domain с lib ES2022 и types: [] без DOM/Node. Vitest проверяет правила, сценарии, адаптеры и действия через React-интерфейс.

## Соглашения кода

TypeScript strict и noUncheckedIndexedAccess; readonly-контракты, именованные экспорты, PascalCase для React-компонентов и kebab-case для остальных модулей. Prettier задаёт формат. Пользовательские тексты принадлежат App. Не использовать innerHTML для пользовательских данных.
